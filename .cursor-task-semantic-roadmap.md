# Implementation Spec: Semantic Knowledge Mapping

## Problem
The current roadmap implementation is "mechanical" (purely heading-based) and has lost the detailed "guide" content in each card. Each card now only shows a title and a one-sentence "signpost" (purpose), which is often duplicated as the "takeaway," causing the frontend to hide it.

## Objectives
1. **Semantic Restructuring**: Group headings into "Semantic Pillars" or "Logical Movements" that reflect the author's underlying argument structure.
2. **Content Restoration**: Ensure each roadmap card contains a distinct Signpost (why it matters), Takeaway (what it says), and Reading Summary/Bullets (how to absorb it).
3. **Hierarchy with Meaning**: Maintain the heading hierarchy but prioritize semantic clustering over raw title extraction.

## Changes

### 1. `backend/services/knowledge_mapper.py`
- Update `KnowledgeMapper` to support "Semantic Nodes" which can cluster multiple heading nodes.
- Update `nodes_to_reading_guide_items` to differentiate between `purpose` and `takeaway`.
- Add a method to "cluster" headings based on semantic affinity (provided by LLM).

### 2. `backend/services/llm_service.py`
- Refactor `generate_roadmap` to be a multi-pass process:
    - **Pass 1: Semantic Segmentation**: Send heading outline + snippets to LLM to identify "Logical Pillars."
    - **Pass 2: Purpose & Summary Generation**: For each Pillar/Segment, generate:
        - `purpose`: A signpost sentence (e.g., "Establishes the foundation for X").
        - `takeaway`: A 2-3 sentence summary of the core argument.
        - `reading_summary`: A concise absorption summary.
        - `reading_bullets`: Key points for quick scanning.
- Ensure `generate_roadmap` returns a full tree of `ReadingGuideItem` models with all these fields populated.

### 3. `backend/api/books.py`
- Ensure the `/reading-guide` POST endpoint correctly triggers the new semantic `generate_roadmap` logic.

### 4. `frontend/src/components/ReadingGuidePane.js`
- Adjust visibility logic to ensure `takeaway` and `reading_summary` are displayed prominently alongside the `signpost`.
- Refine CSS for `roadmap-card` to handle richer content without looking cluttered.

## Success Criteria
- The roadmap shows logical "Pillars" (e.g., "Phase 1: The Problem", "Phase 2: The Solution") instead of just "Chapter 1", "Chapter 2".
- Each card displays a helpful "Signpost" and a substantial "Guide" (Takeaway/Summary).
- No content is hidden due to duplication unless it truly adds no value.
