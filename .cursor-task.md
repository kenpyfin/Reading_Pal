# Reading Pal 6: Fixing Over-Aggressive Roadmap Filtering and Granularity

The goal is to resolve the issue where the whole-book roadmap generation is too aggressive in filtering and clustering, resulting in too few cards (e.g., only 4 cards for a whole book).

## 1. Adjust KnowledgeMapper Thresholds (Substance Gate)

File: `backend/services/knowledge_mapper.py`

- **Relax non-structural heading filter:**
    - Reduce `content_len < 40` to `content_len < 20`.
- **Relax tiny title/content filter:**
    - Reduce `(title_len <= 3 and content_len < 20)` to `(title_len <= 2 and content_len < 10)`.
    - Reduce `(title_len <= 10 and content_len < 5)` to `(title_len <= 10 and content_len < 3)`.
- **Relax "Segment X" check:**
    - Reduce `content_len < 50` to `content_len < 15` for numeric/segment titles.
- **Expand Structural Keywords:**
    - Add common book section names to `STRUCTURAL_KEYWORDS`: `"secret"`, `"story"`, `"lesson"`, `"step"`, `"law"`, `"principle"`, `"rule"`, `"conclusion"`, `"summary"`.

## 2. Adjust LLMService Segment Thresholds

File: `backend/services/llm_service.py`

- **Lower thin-segment skip threshold:**
    - Reduce `segment_word_count < 10` to `segment_word_count < 5` in `_build_semantic_reading_guide_items`.

## 3. Refine Architect (Segmentation) Prompt

File: `backend/services/llm_service.py`

- **Update `segmentation_system` prompt:**
    - Replace "prefer fewer, richer pillars over many shallow ones" with:
        "Aim for a balanced granularity—typically 10-15 pillars for a full book, or 3-5 for a short paper/chapter. Avoid over-clustering; every distinct major point or sub-topic should be its own pillar."
    - Replace the instruction to skip chapter breaks with:
        "Headings and chapter breaks are strong signals for pillar boundaries; use them as primary guides unless they are clearly repetitive layout noise (like page numbers or headers/footers)."
    - Explicitly state: "If in doubt, preserve the section as a separate pillar rather than merging it."

## 4. Verification

- Run `tests/test_knowledge_mapping.py` to ensure no regression in core mapping logic.
- Verify that more segments are reaching the "Mentor" phase and resulting in more cards.
