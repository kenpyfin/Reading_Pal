# Implementation Spec: Semantic Knowledge Mapping ("Architect" Approach)

Refactor the knowledge mapping and roadmap generation from a mechanical heading-based approach to a semantic, logical pillar approach.

## Goals
1.  **Semantic Clustering**: Use LLM to identify the book's logical architecture (movements/phases) instead of just grouping headings.
2.  **Content Restoration**: Ensure Purpose (Signpost) and Takeaway (Substance) are distinct and always visible.
3.  **Mentor Voice**: Update prompts to enforce a substantive "Guide" experience.
4.  **UI Transparency**: Remove aggressive deduplication that hides content.

## Changes

### 1. Backend: `backend/services/llm_service.py`
- **Update Segmentation Prompt**: Focus on "Logical Movements" and "Architectural Pillars".
- **Update Card Generation Prompt**: Enforce "Mentor Voice" and distinct Purpose vs. Takeaway.
- **Remove Deduplication**: Remove the logic that sets `takeaway = None` if it matches `purpose`.

### 2. Backend: `backend/services/knowledge_mapper.py`
- **Update `normalize_semantic_segments`**: Ensure it supports the new architectural pillars and doesn't just fall back to headings too easily.

### 3. Frontend: `frontend/src/components/ReadingGuidePane.js`
- **Remove Deduplication**: Change `showTakeaway` logic to always show the takeaway if it exists.
- **UI Enhancements**: Ensure "How to read this segment" section is prominent.
